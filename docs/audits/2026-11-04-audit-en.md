## Verdict

The skeleton is better than most hand-built static sites. The JavaScript is defensive, the Python
checkers prove they can still fail, there are no broken internal links among 1,512 checked, and
there are no JS errors on any page. The fragility comes from two habits that are typical of
building across many AI sessions:

- **Work committed in halves.** EN finished and committed, RO left behind.
- **Template copy-paste.** A page is cloned, and the parts that should change don't.

Both produced bugs that are live today. Neither needs a rewrite. They need a handful of cheap
consistency checks, plus holding the comments to the same "must be true" standard the checkers
already meet.

## 1. Solid — protect this

- **Self-testing tooling.** `check-noopener.py --self-test`, the two-way STALE/NAKED gate in
  `check-uc-banner.py`, and the prune safety proof with its fault-injecting self-test all hold the
  rule "a guard nobody has seen fail is decoration". All of them pass today. They use only the
  standard library and handle newlines carefully.
- **Defensive JavaScript.** Almost every mechanism returns early when its DOM is missing
  (`en/script.js:269, 392, 489, 583, 813, 1415`). Fetches check `response.ok` and fall back
  visibly. Fetched or variable text goes in through `textContent`, not `innerHTML`.
- **Links and assets.** There are 0 broken internal links, assets or `#fragment` targets across
  all 57 pages, every `target="_blank"` link is protected, `lang` is correct on every page, and no
  image is missing `alt`.
- **MECANISM 11 (generated sidebar).** It is well designed: anchors are read from ids rather than
  from translated headings, it runs a single document-order query, and it uses delegation that
  survives `replaceChildren`. Its comments are among the best in the project.
- **CSS structure.** It keeps its promise: 32 modules plus 00.1/00.2, with `@media` confined to
  00.2. For 5,300 lines there are few duplicates.
- **EN/RO parity where it is finished.** `style.css` and `bibliography.js` are code-identical
  across languages once comments are stripped.
- **Process honesty.** Under-construction banners, a backlog that records corrected premises, and
  a documented one-command deploy and rollback.

## 4. The comments as a teaching method

**Where it works:** comments that explain a failure mode or a decision the code can't express.
Model examples:
- MECANISM 05's warning about per-link listeners silently breaking (`en/script.js:238-254`)
- "label from the id, not the translated heading" (`:1472-1475`)
- the "DATA vs a COPY OF DATA" lesson (`:1390-1399`)
- "a guard nobody has seen fail is decoration" (`check-noopener.py`, `lint.yml`)

These are the house style worth spreading.

**Correction to a belief in the code:** the `style.css` manifest (`:15-22`) says the JS "extracts
these custom annotations". It doesn't. MECANISM 08 shows each file as raw text. Today the tags
serve human readers only, and no tool checks them.

### Restating comments

`style.css` has about 2,000 tagged trailing comments, and about 65% restate the value. They come
from a generator: the same boilerplate repeats ("Character scale —" 65×, "Glyph spacing —" 47×),
and the same boilerplate produced the 48 contradictions. `script.js` has about 110–130 of about
206 trailing comments that restate their line. Your own legend rules these out, and they bury the
good comments.

### How to improve the method (ranked)

1. **Make comment claims checkable.** Add a `tools/check-comment-refs.py` with a `--self-test`,
   wired into `lint.yml`. It would check:
   - every `MECANISM NN`, `Module NN.N` and `BACKLOG #NNN` exists;
   - every tag is in the legend;
   - legend counts match the code;
   - `<meta charset>` sits within 1024 bytes.

   This applies the project's best idea (self-testing guards) to its comments.
2. **Require a source for teaching claims.** Any `@pedagogy` that makes a performance, security or
   spec claim cites MDN or the spec (`@source:`). That rule alone would have caught most of the
   wrong-teaching table.
3. **Retire the templated per-declaration CSS comments, not the method.** Use one `@reason` per
   rule-block, and line comments only for non-obvious values (magic numbers, vendor-prefix order).
   Start with the 48 contradictions. If a generator writes comments again, it should write none
   rather than boilerplate.
4. **Keep volatile numbers out of prose.** Point to the variable or selector, or anchor history to
   a commit ("at #013, commit `9bad9c8`: 1490 `<li>`").
5. **Give each comment layer one job.**
   - The banner says *what the mechanism is*.
   - Tag blocks say *why and the pitfalls*.
   - Trailing comments say *only the non-obvious*.

   Today MECANISM 01–04 often say the same fact three times.
6. **Write the head-template commentary once.** The same ~25 comments, with the same errors, are
   copied into 46+ pages. Keep one annotated reference page and a short pointer in each page.
7. **Extend the legend** with a Tooling (Python/YAML) section. Define or drop `@tag`, `@scope` and
   `@file`, which are in use but not defined, and `@selector`, `@todo` and `@cluster`, which are
   defined but unused. Keep tag meaning the same across EN and RO.
8. **Optional:** make the blueprint page *use* the tags, for example by highlighting `@pedagogy`
   and `@warning` lines. That would make the manifest's claim true.
